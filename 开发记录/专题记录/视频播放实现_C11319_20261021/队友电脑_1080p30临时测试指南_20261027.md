# 队友操作：临时测试显示器1080p30逐行输入

测试平台：队友电脑的RTX 4070 Laptop GPU → 原HDMI线 → FPGA原来使用的HDMI显示器。

目前Windows完整模式列表已确认：1920×1080有60Hz和59Hz。此次通过电脑发送一组固定的1080p30逐行时序，取得显示器的实际接收证据。项目视频内容继续保持1080p15；若采用30Hz显示扫描，每张内容帧显示两次。

## 1. 打开NVIDIA自定义分辨率

1. 打开 **NVIDIA控制面板**。
2. 左侧“显示”→“更改分辨率”，选中外接的 **HDMI** 屏幕。
3. 点“自定义”，勾选“启用显示器未提供的分辨率”，再点“创建自定义分辨率”。
4. NVIDIA若出现自定义时序提示，由队友阅读后决定是否继续本次测试。

这一路径与“测试”按钮的用途已核对[NVIDIA官方创建步骤](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-us/mergedProjects/Display/To_create_custom_timings_for_your_HDTV_display.htm)。

若“自定义”或“创建自定义分辨率”呈灰色，截图发回该窗口即可。

## 2. 输入显示模式

| 字段 | 数值 |
| --- | --- |
| 水平像素 | 1920 |
| 垂直行数 | 1080 |
| 刷新率 | 30Hz |
| 颜色深度 | 32位 |
| 扫描类型 | **逐行 / Progressive** |

## 3. 输入手动时序

展开“时序 / Timing”，将“标准 / Standard”改为 **手动 / Manual**。

| 字段 | 水平 Horizontal | 垂直 Vertical |
| --- | ---: | ---: |
| 有效像素 / Active pixels | 1920 | 1080 |
| 前沿 / Front porch | 88 | 4 |
| 同步宽度 / Sync width | 44 | 5 |
| 总像素 / Total pixels | 2200 | 1125 |
| 极性 / Polarity | 正 / + | 正 / + |

如果界面有“后沿 / Back porch”字段，对应水平148、垂直36。

填完后核对计算结果：**像素时钟74.25MHz、水平33.75kHz、垂直30.000Hz**。拍下完整参数页，保留扫描类型和时序表。

以上对应CTA VIC34标准1080p30时序，参数来自[Linux DRM CTA模式表](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/+/refs/heads/master/drivers/gpu/drm/drm_edid.c)。字段含义和Manual选项见[NVIDIA自定义分辨率对话框说明](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-us/mergedProjects/Display/Custom_Timings_Dialog_Box.htm)。

## 4. 点击“测试”并记录结果

点击 **测试 / Test**。

- 如果外接屏正常显示电脑桌面，确认结果并保存这组自定义模式，再在“更改分辨率”中选中它、应用。
- 如果外接屏显示“无信号”“超出范围”或黑屏，等待NVIDIA测试恢复原画面。恢复后记录错误提示和结果。
- 若需要从内屏恢复，使用笔记本内屏上的NVIDIA控制面板，将外接HDMI屏设回1920×1080、60Hz。

NVIDIA官方说明测试不被接收时画面通常会在数秒后恢复；本指南沿用其测试入口。[NVIDIA测试与恢复说明](https://nvidia.custhelp.com/app/answers/detail/a_id/759/kw/gfnios)

## 5. 确认实际输出并发回

测试成功后打开Windows“设置 → 系统 → 屏幕 → 高级显示”，选 **显示器2：HDMI**。

需要的证据是：

1. NVIDIA完整参数页截图：1920×1080、30Hz、Progressive和手动时序。
2. Windows截图：**活动信号模式为1920×1080、30Hz**，同时保留桌面模式一行。
3. 一句现场结果：“外接屏桌面稳定显示约20秒”，或具体的黑屏/无信号现象。

以实际活动信号30Hz和外接屏画面作为接收证据。若桌面模式30Hz、活动信号仍为60Hz，将这两行原样截回继续核对。

## 结果将怎样使用

- 目标屏实际接收1080p30：可继续评估每帧重复两次的1080p15播放方案。
- 目标屏测试无信号或驱动拒绝：保存错误和参数，结合现有EDID及FPGA输出能力重新选择硬件路线。

FPGA当前HDMI四对引脚采用Emulated差分，已验证165MHz串行链。1080p30的371.25MHz发射需要另外完成引脚、电气和实现能力核验。电脑测试用于解决接收端问题，FPGA端实现另有独立证据链。

## 阶段二：电脑复现C33/C36的15Hz时序

2026-10-27用户已确认：上述1080p30逐行模式，外接屏桌面约20秒完整稳定、无闪烁或间歇无信号。这项接收测试已完成。

继续新增一条自定义模式，保留已成功的30Hz配置。步骤与前文一致，改用下表参数：

| 字段 | 水平 | 垂直 |
| --- | ---: | ---: |
| 有效像素 | 1920 | 1080 |
| 前沿 | 8 | 4 |
| 同步宽度 | 8 | 5 |
| 总像素 | 2000 | 1100 |
| 同步极性 | 负 / − | 负 / − |

- 显示模式刷新率：**15Hz**。
- 扫描类型：**逐行 / Progressive**。
- 时序标准：**手动 / Manual**。
- 预期结果：**像素时钟33.000MHz、水平16.500kHz、垂直15.000Hz**。

这组几何、消隐和时钟与C33/C36一致；负同步极性按其映射网表恢复的控制符记录。参数填完后拍照，再按“测试”。

需要发回：

1. 15Hz手动参数页。
2. Windows活动信号模式是否为1920×1080、15Hz。
3. 外接屏实际是否完整稳定显示桌面。

如果驱动在发送前拒绝该参数，保留错误提示，记为“测试未发送”；如果进入测试后显示器无信号，等测试恢复并记录结果。以实际活动信号和屏幕画面作为此次接收依据。

结果用途：电脑同组15Hz时序正常而FPGA无信号时，继续追FPGA的TMDS符号、数据岛与消隐调度；电脑实际发送后目标屏仍无信号时，30Hz接收成功的路线继续保留。
