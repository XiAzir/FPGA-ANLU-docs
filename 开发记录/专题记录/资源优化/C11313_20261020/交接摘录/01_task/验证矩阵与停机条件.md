# 实施流程、最小验证矩阵及停机条件

## 阶段0｜只读建立证据

1. 读取两仓`AGENTS.md`、`开发记录/当前状态.md`、协作/工具约定；记录`git status --short`、分支与HEAD；确认C11206/C11312当前存在，检查两个仓库分支匹配。
2. 原项目 `development/player_spectrum_trace/build/manual/AC201_tf_hdmi_phy.area`、`AC201_tf_hdmi_phy.ts`、`AC201_tf_hdmi_chk.timing`、`AC201_tf_hdmi_exception.timing`；与 `.al`、源、`stage_evidence`和实物反馈对应。
3. 运行本包 `03_tools/resource_compare.py`（只读），复核四版既有报表。检查当前工作树与本包快照是否漂移；漂移时不重置，依据新源码重新判断。
4. 排列前五名面积热点/真实复制逻辑/路径超宽原因，并对每一候选写明验收方式与预期边界。保留旧基线的hash。

## 阶段1｜最小单点优化，先做能客观证明的更改

1. 在隔离工程中选择**一个**模块，保存更改前后完整文件和hash、标注工具和唯一实验ID。
2. 先运行原有测试，证明候选工作区基线正确；缺少工具即按实际情形记录，并用可执行静态检查补充，不得伪造通过。
3. 实施有数学证明的资源优化，例如宽数值范围分析、同一时钟域的共享算术；**禁止无证据删分支、修改出错时行为、减少检测**。
4. 至少用原始gold/reference和专门负例断言比较优化前后。仅跑一个几百周期smoke不足以宣布功能等价。
5. 重新综合并分析`gate.area`；收益有限时不要盲目跑昂贵P&R。收益合理才运行`physical`、必要时`hold`、最终时序/面积。
6. 记录同一个RTL改动的前后总量、模块量和关键路径；同一处参数/SYNT设置必须一致。单纯不同布局不能说“逻辑优化”。

## 正向+负向测试建议（按模块裁剪，不能全部省略）

| 范围 | 必需正例 | 必需负例 | 结果判据 |
|---|---|---|---|
| FAT32目录 | MBR/VBR、8.3根目录、BMP+WAV、多分区几何、有效FAT选择 | BPB坏值、越界、短块、无有效根、循环/超限、超时 | error code/文件位置、顺序一致；坏输入不得假PASS |
| 文件映射器 | 连续+碎片簇链、前向与回退、512字节边界、4096簇允许边界 | 越界/EOC/环/非法簇/请求时长 | 各数据字节、LBA、握手、错误码均可比 |
| BMP及缩放 | 320×240、800×600、191×321 top-down、512×128、可用的宽/高边界 | 文件截断、BMP头非法、宽高0、越界偏移/stride | 全像素或逐行CRC与gold一致，黑边方向一致 |
| WAV/仲裁 | 48kHz PCM16 mono、音源切换、BMP同时加载 | 非法格式、短扇区、CRC不良、突发延迟 | PCM样本序列、watermark/错误不回归 |
| FFT/频谱 | 实际4096+样本、帧间变化、全24频带、冻结、切源和衰减 | 全零ROM/坏系数、丢样/超时、reset/切源碰撞 | 定点参考逐帧比对，图上可见像素非零 |
| 视频/HDMI | 全active像素RGB888、SOF/TLAST、行列、音视频时序、持续多帧 | 失步、FIFO欠载、背压、不完整行、变化audio样本 | TMDS串行解码、audio packet与参考一致 |
| 复位/CDC | 50MHz输入、PLL锁定等待、异步域释放与标志切换 | lock抖动/复位重复、FIFO压力 | 不产生未知态、漏脉冲或伪一致 |

**原有可复用用例入口：** `development/player_spectrum_trace/sim/`（原子快照、FFT、BMP、SPI裕量、实音频）和 `development/system_verification_20261016/`（完整媒体链比较，注意应用接口级SDRAM模型的边界）。根据模块选择真实可用的脚本，检查被测module和gold不是“旧/错的top”。

## 阶段2｜TD 构建阶段的强制要求

推荐从隔离后的候选目录调用源工程`build_candidate.ps1`同型包装器，不绕过`build_evidence.ps1`。原工程脚本例：

```powershell
# 在独立候选目录中（确认脚本已适配新的目录与相对路径）
pwsh -File ./scripts/build_candidate.ps1 -Stage synthesis
pwsh -File ./scripts/build_candidate.ps1 -Stage physical
# 如果需要官方hold修复
pwsh -File ./scripts/build_candidate.ps1 -Stage hold
# 仅当全部门槛满足、工具许可证就绪、需要产物时
pwsh -File ./scripts/build_candidate.ps1 -Stage bitstream
```

已有wrapper会检查RTL快照、脚本hash、生成日志标记、特定ROM初始化告警HDL-5105、最终Setup/Hold负值。如果复制工程导致保护失败，应修复新目录路径引用，**不得删除检查项**。阶段证据必须匹配，重新从synthesis建立当前快照；避免将旧DB/bit混入新候选。

## 停机/拒绝交付门槛

- 工作目录含用户未提交改动且无法隔离保存，或工具实际无法编译、许可证无效：停止产生bit，输出阻断原因/局部成果。
- 设计与gold的一个有效像素/音频样本/关键控制事件不一致且无法解释：不可交付。
- 负例（CRC、坏BPB、越界/EOC/环）未按期待出错：不可交付。
- BRAM、LUT、DSP或Slice超出器件容量；任何最终Setup/Hold WNS/TNS负值：不可交付。
- 以False Path、异步例外、忽略复位时序、缩短PLL等待或改变约束来“改善时序”：拒绝当作等价资源优化。
- 源hash或Tcl hash不匹配/ROM系数未绑定、使用陈旧PR DB或位流：不出bit。
- 视频/数码管/HDMI物理故障未实板重现：报告`BOARD_NOT_TESTED`，不能称“根因已修复”。

## 报告输出标记

独立字段：`static_review`、`sim_unit`、`sim_media_full`、`gate`、`route`、`final_sta`、`bitstream`、`board`，每一项应为`PASS/FAIL/NOT_RUN/BLOCKED`。**绝不能用“全部通过”代替逐项范围。**
