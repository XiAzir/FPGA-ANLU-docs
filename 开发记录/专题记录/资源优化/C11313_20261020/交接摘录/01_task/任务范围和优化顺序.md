# 工程任务书｜C11312保功能资源瘦身

## 0. 任务界限

**允许实施的工作：**本地隔离副本中的RTL设计优化、候选回归、阶段重建、完整P&R/STA、生成候选bit（须通过功能与时序关卡）、提交本地分析报告。**禁止：**直接改已封存C11206/C11312历史工程/bit，改TF原始素材和受保护IP，将某种颜色量化或降低画质作为未经许可的默认优化，调宽时钟/改SDC让报表变绿，发送板端操作或推送远端。

请确保 `development/player_spectrum_trace` 源/约束/模型先被SHA或Git blob冻结；在新的独立目录或独立受控工作区推进。例如在不与已有文件冲突的前提下使用 `development/player_spectrum_resource_fit/`。复制所需的 `src`、`sim`、`scripts` **连同所有相对引用的依赖**，不要把历史 `build/`、`checkpoints/` 的旧DB当成新工程结果。若目录脚本硬编码某些路径或stage bit名称，应做最小适配并用回归验证，不要关掉护栏。

## 1. 首轮最重要的可交付结果

1. 原始C11312和稳定C11206对照确认：代码SHA/HEAD、工具版本、最终 P&R 实例报告、最终setup/hold、阶段完整性。
2. 解释逻辑LE、LUT、MSlice/Slice、BRAM、DSP不同指标为何不等价，确认优化方向。
3. 至少一个独立可复现的优化尝试，有原始/优化的RTL差异、功能正负回归、综合或最终P&R面积对照；失败也必须留证。
4. 对所有尝试输出：功能影响、预计/实测节省、资源正负收益、时序增减与新错误、下一步。
5. 为后续板测保留**一套可信的、最小观测链**，不把C11312数码管输出假定为正确。

## 2. 优先级按面积+保功能+物理收益共同决定

### P0：FAT32目录解析 (`u_catalog`, 3051 LE)

文件：`development/player_spectrum_trace/src/user_source/hdl_source/fat32_catalog.v`。

源码中确有大量32/64位中间量、几何有效性判断与分区表。先绘制计算图/信号用域、确认是否有重复宽移位、比较器、除法或“同时计算但并非同时需要”的运算；考虑显式阶段复用、正确位宽化、减少重复算术。**但不能取消MBR/VBR识别、活动FAT、根目录遍历或错误识别；不能把非正常数据当成功。** 先复制该模块建立独立testbench，包括MBR/VBR、合法BPB、保留分区范围、越界/畸形、目录链/碎片、空目录、超时、EOC/环等负例。重构算术时验证所有中间字段与原版结果一致。

### P1：BMP缩放和媒体接口 (`u_bmp_file_player`, 2828 LE；`u_scale`其中1737 LE)

文件：`bmp_scale_engine.v`、`tf_bmp_file_player.v`。

关键观察：多个32位几何状态寄存器、逐拍迭代除法、行地址和宽乘法。固定640×480输出和输入上限1024×768，先利用数学范围**证明**某些位宽可缩小，再设计流水顺序复用或常数乘法替代。不能只缩窄而使`top-down`、非标图高、奇数行stride、右下边界、最小1x1、错误偏移/文件长度测试损坏。必须保留当前RGB888数据路径、SDRAM打包格式和黑边方向。

### P2：FFT/频谱 (`u_pcm_waveform`, 1988 LE、17 BRAM9K、3 DSP)

文件：`player_pcm_waveform.v`、`player_spectrum_analyzer.v`、`spectrum_coeff_rom.v`、`spectrum_hann.mem`、`spectrum_twiddle.mem`。

不要简单删除FFT或改低点数（原功能必须保留：1024点、24频带、音源切换、进度/看门狗、冻结/衰减、非空可见柱体）。先检查波形绘制front/back数组、BRAM/存储端口，Butterfly计算位宽、24段比较器/缓存、可共享逻辑；要考虑合成后的宏推断、系数ROM初始化和时序。FFT当前使用了多份RAM读bank换并行读，贸然改单RAM可能改变读延迟/有效时钟，必须证明整个时序合同。不能因为测试只跑固定正弦就删掉系数ROM内容。保持C11306历史twiddle全零问题作为负面案例。

### P3：FAT32文件映射器两份 (`u_bmp_file_mapper`, 1180 LE；`u_wav_file_mapper`, 1288 LE)

源码：`fat32_file_sector.v`。实例分别服务BMP和WAV，不能直接合二为一破坏并发。重点审计缓存中不必要的双份状态、63位扩展与加法、32/33/64位地址检查、Brent环检测、文件4096簇上限、前进/回退寻址。任何位宽优化都须保持边界包含关系及数据有效信号时序。对文件读负例、每种错误码和无声失败做精确回归。

### P4：其他明显异常与诊断 (`u_video_rgb_to_axis_640x480`, 710 LE；诊断若干模块)

`video_rgb_to_axis_640x480.v` 源文件非常短，但物理层级报告显示710 LE，值得查是否路由驱动器复制、时钟使能分解或层级优化记账；要先证实减少原因。该模块另有行尾计数/TLAST疑点，这属于**既有逻辑缺陷**，如需修复，应当单独提交并做前后差异测试，不与资源优化混合。

`player_fault_snapshot.v` / `player_status_monitor.v` / `status_hex595.v` / `player_status_mailbox.v` 相关观测总体占不少寄存器，但用户实板曾看到数码管诊断字损坏。可以做简化独立数码管固定码/错误码，而不能毫无证据地砍掉全部诊断。任何控制跨域握手都要保留原子性。

## 3. 优化目标与考核

- **第一目标**：保持原功能，最终P&R Slice ≤90%（相对于当前99.10%需减少至少约892 Slice）。这个数字仅是目标，不是保证，也不允许靠破坏功能/约束换取。
- 第二阶段再考虑≤85%（需减少至少约1382 Slice）。
- 所有报告必须给出`route`或`post-hold`实际可比口径、LUT、FF、BRAM9K、DSP、Setup/Hold WNS/TNS以及STA coverage/未约束端口。
- 任何版本即使Slice下降，如果BRAM超限、关键路径setup/hold失败、FAT32坏数据被接受、视频/音频异常、观察能力丢失，都不可标记“可交付”。
- 面积更小也**不能证明已经修复C11312板端问题**；该项目还有供电/PHY/CDC/SDRAM实际控制器等未闭环证据。

## 4. 不属于本轮任务

- 720p60、普通MP4/H264解码、TF原生4-bit SD、SPI频率上调、RGB565/RGB332全面改造；这些是**独立后续课题**。
- Flash启动、TF格式化/重写、硬件上板、远程仓库推送/PR合并。
- 用新的“构建成功”报告覆盖原硬件失败证据。
