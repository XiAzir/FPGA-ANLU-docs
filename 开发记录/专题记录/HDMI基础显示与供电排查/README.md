## 判定方法

- 固定顺序中的全屏纯黑是测试内容，不应单凭它判定链路故障。
- 各幅纯色及渐变条应完整、稳定，顺序应重复；检查连续 2～3 轮。
- 若在几乎每幅非黑画面之间插入黑屏、画面反复只出现一瞬、顺序被打断，或显示器出现“无信号”/重复识别输入，应继续检查显示链路。
- 手册此处没有标注各幅停留时间；不能仅凭黑屏 1～2 秒、画面约 0.5 秒认定正常或异常。
- 这些画面由 FPGA 内部测试源生成，不是从 TF 卡读取的 BMP 图片；此图是内容对照，不是板上录屏。

### 随包源码/报告发现（不等同于实测）

检查目录：E:\QQ CACHE\Download\安路资料\小梅哥\AC201_AL_board_test(不包含SD_SRAM_EEPROM)\AC201_AL_board_test

1. src/user_source/hdl_source/design_top_wrapper.v：HDMI 核心参数为 1280×720，有效总时序 1650×750，VIDEO_VIC=69，VIDEO_TPG=Enable。外部 video_source_test 的 1920×1080 参数在内置测试源启用时不是当前有效图像源，不把这两组尺寸直接认定为故障原因。
2. al_ip/pll_hdmi1_4b/pll_hdmi1_4b.v：输入假定 50 MHz，生成文件注明像素时钟 73.333333 MHz、串行时钟 366.666667 MHz，后者相移 90 度。按源码及 50 MHz 输入计算，帧率约 59.259 Hz；实际晶振/引脚时钟尚未测量。标准 720p60 时序的像素时钟为 74.25 MHz。现配置与标准时序有差异，需核查兼容性，不能仅凭差异断言黑屏原因。
3. .ipc 中请求 75/375 MHz，实际生成 .v 注明 73.333333/366.666667 MHz；后续生成 PLL 须核对实际可实现值，不能只看请求值。
4. timing.sdc 把像素时钟和串行时钟声明为 exclusive，两者在实际串行器同时运行并传送数据，不能用此设置证明跨域时序安全。周期 13.5/2.7 ns 也与 .v 注明频率不完全一致。
5. AC201_AL_board_test_Runs/syn_1/AC201_AL_board_test_gate.timing 是综合阶段报告，仅列 50 MHz DeriveClock，覆盖率 86.32%。这份报告不能证明 HDMI 高速串行路径已经通过布局布线后的时序检查；best_result/phy_1 未找到相应完整布线后 timing 报告。
6. Linux DRM 的公开 CTA 模式表：VIC 4 为 1280×720@60Hz 16:9；VIC 69 为同样像素时序但 64:27 显示比例。69 不是非法数值，但普通 16:9 测试应检查使用意图及接收兼容性，不把它作为已证实根因。
