# 开发记录

本文件夹是安路赛题 1（AC601 + AC201 / EG4S20BG256）的统一留档位置。

读取条件：留档、交接或修正记录时。本文件包含详细留档规则；不要为读取本规则加载无关的板卡、工具或历史排查文档。

`main` 默认工程仓 `FPGA-ANLU/` 与资料仓 `FPGA-ANLU-docs/` 位于同一父目录。实际开发工程在 [工程仓](../../FPGA-ANLU/)；文档、资料与本文件夹在 [资料仓](../)。少量基本规则与主题入口见 [项目 AGENTS.md](../../FPGA-ANLU/AGENTS.md)。两仓 `XiAzir` 分支保留原本机布局；两仓应使用同名分支，具体克隆步骤见 [协作与目录](../开发约定/协作与目录.md)。

## 入口与维护

- [当前状态](当前状态.md)：接续开发、判断进度或交接时读取；每次有状态变化时更新现状，不堆叠历史。
- [工作日志](工作日志/)：按北京时间分日追加，以 `YYYY-MM-DD.md` 命名；每次完成、未完成、阶段性进展、失败/受阻或暂停交接均记录。
- [专题记录](专题记录/)：收纳必要的详细证据、截图、参考图和排查经过，其他记录用链接引用。

长任务到达关键阶段先留档，结束前再补最终状态。纯说明任务可以只记一条“说明已完成，开发验证状态不变”。记录应足够让下一次工作直接接续，不必复制完整聊天或每个工具调用。

接续工作时按任务查相关最新日志和专题片段，不一次加载全部日志、专题或开发约定。记录日期与时间使用北京时间（Asia/Shanghai）；首次建立记录可以汇总已有事实，但须注明来源，不补造过去的执行时间或测试结果。

## 必须保留的信息

1. 时间、任务、阶段和状态：已完成 / 进行中 / 未完成 / 受阻 / 暂停。“已完成”只能用于有证据达到目标的范围。
2. 实际动作与产物：做了什么、涉及文件；必要的命令、版本、硬件连接和参数。建议与计划写明“尚未执行”。
3. 验证与结论：方法、结果和证据位置。区分文件检查、静态核查、仿真、综合、布局布线/时序、下载、实物运行；用户现场反馈注明“用户反馈”，不能写成代理直接测量。
4. 未完成项、原因和影响：停在哪里、为什么、是否阻碍下一步。没有测试写“未验证”，不写“正常”。
5. 下一步与依赖：能直接接续的具体操作；需要用户进行实物操作时，写清操作与观察点。

完整工具输出可留在工程日志中，摘录关键错误并链接原日志。不要将密码、令牌或许可证正文写入记录。阶段记录写好后，任务结束前补最终状态，并核对记录与实际文件及执行结果一致。

新记录中的入库文件优先使用相对链接；历史日志、来源校验、冻结记录和工具输出中的实际绝对路径保留为当时证据，不因 `main` 的克隆布局而批量替换。被忽略的日志、位流和外部备份不随克隆提供，引用时注明其保存位置和取得条件。

## 日志条目模板

```text
### HH:mm｜任务名｜已完成 / 进行中 / 未完成 / 受阻 / 暂停（注明阶段）

- 动作/产物：实际完成的工作及文件路径；计划写明“尚未执行”。
- 验证/结论：检查方法、结果、证据链接；用户反馈、静态核查、编译与上板分别注明。
- 未完成/原因/影响：停在哪里、为什么、影响什么；无测试则写“未验证”。
- 下一步：具体操作与必要依赖。
```

可根据任务合并条目，但不能遗漏影响复现和判断的关键版本、参数、错误、工程路径、硬件连接、测试范围和未确定事项。工具完整日志留在工程目录，摘要链接它；资料来源、截图和人工说明留在本目录或其他资料目录。

首次建立日志中的历史汇总必须注明来源与日期边界，不补造执行时间。旧判断被新证据修正时，保留旧日志，在新条目解释变化，同时更新当前状态与相关清单。
