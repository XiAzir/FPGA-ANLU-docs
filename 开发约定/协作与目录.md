# 协作与目录

读取条件：整理目录、导入或修改参考工程、使用子代理时。无需因此加载其他主题的详细约定。

## 协作

- 按用户已授权的任务持续推进；阶段性结果、失败和未完成事项均须留档，不能只在聊天中说明。
- 当子代理能显著提高效率时可以使用，须给出明确范围、输入、输出和验证要求；必要时提供 spec。避免多个代理同时修改同一文件。
- `AGENTS.md` 仅保留少量基本规则、触发条件和文档路径；主题详情写入资料目录的对应文档。增加新主题时新增按需读取入口，不把细节重新展开到 `AGENTS.md`。

## 目录职责

- 工程仓目录为 `FPGA-ANLU/`，资料仓目录为 `FPGA-ANLU-docs/`；`main` 分支默认它们位于同一父目录。本文中的相对链接以当前文档所在目录为基准。
- [工程仓](../../FPGA-ANLU/)存放实际开发的 TD 工程、HDL、IP、引脚与时序约束、仿真、构建/下载脚本，以及编译报告、工具日志、位流等工程产物。TD 使用的工程与位流完整路径采用纯英文，避免中文和空格。
- [资料仓](../)存放入库的赛题、手册、图纸、教程、原厂参考工程、参考素材，以及开发说明、分析文档和人工记录。原始资料包、安装程序、许可证和重复归档另行备份，不随 Git 克隆提供；索引中的外部备份路径只表示原有存放位置。
- 修改或编译参考工程时，将所需工程复制到项目目录，保留资料目录中的原件，不直接修改原始参考。
- 两处 `AGENTS.md` 是必要的自动读取入口。工程工具自动生成且构建/排错所需的日志与报告随工程保存；人工摘要及其链接写入资料目录。
- 统一留档目录：资料目录下的 `开发记录`。不另建分散的聊天总结或进度目录。
- 建立目录规则前已有的项目内参考说明暂作历史副本保留；后续维护统一在资料目录，不继续向旧位置写入文档。

## 分支与克隆

两个仓库都维护 `main` 和 `XiAzir`。`main` 用于上述通用同级目录布局；`XiAzir` 保留原开发机的工程目录与资料目录架构。接续开发时两仓选择同名分支，不把一仓的 `main` 与另一仓的 `XiAzir` 混用。`main` 不需要设置本机 Git 配置覆盖目录。

在选定的同一父目录打开 PowerShell，执行：

```powershell
git clone --config core.longpaths=true --branch main https://cnb.cool/XiAzir/FPGA-ANLU FPGA-ANLU
git clone --config core.longpaths=true --branch main https://cnb.cool/XiAzir/FPGA-ANLU-docs FPGA-ANLU-docs
```

建议选择较短、不含中文和空格的英文父目录。克隆命令中的 `core.longpaths=true` 用于让 Windows Git 检出仓库内的长路径文件，不解除 TD 软件自身的路径限制；TD 工程和位流仍须遵守上述英文路径约定。两个仓库的本地目录名保持上述名称，以便相对链接和脚本默认路径能够互相定位。仓库网页入口分别是 [工程仓](https://cnb.cool/XiAzir/FPGA-ANLU)和[资料仓](https://cnb.cool/XiAzir/FPGA-ANLU-docs)；跨仓相对链接用于本地同级克隆布局。

克隆只取得已入库文件，不会安装 TD、Icarus Verilog 或许可证，也不包含忽略的构建产物、原始安装包和归档。工具准备见 [工具与工程验证](工具与工程验证.md)。已有历史日志、来源校验和冻结工程中的本机绝对路径是当时的证据，保留原样；它们不定义 `main` 的当前目录布局。
