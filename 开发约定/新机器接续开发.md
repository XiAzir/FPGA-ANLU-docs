# 新机器接续开发

当前接续基线是 **C11206 / `bmp_scale.bit`**。功能、已知波形显示问题和未完成验证以[当前状态](../开发记录/当前状态.md)及[五项扩展总表](../开发记录/专题记录/整机集成/C11206五扩展验收_20261012/README.md)为准。

## 克隆与分支

新机器使用两个仓库的 `main`，放在同一父目录，目录名固定为 `FPGA-ANLU` 与 `FPGA-ANLU-docs`。Windows 建议父目录短、纯英文，例如 `E:/ANLU`；Git 必须启用长路径，以容纳原厂参考和冻结快照的深层目录。

```powershell
git clone --config core.longpaths=true --branch main https://cnb.cool/XiAzir/FPGA-ANLU FPGA-ANLU
git clone --config core.longpaths=true --branch main https://cnb.cool/XiAzir/FPGA-ANLU-docs FPGA-ANLU-docs
Set-Location FPGA-ANLU
```

两仓的 `.gitattributes` 保留原始文件字节，避免换行转换破坏 manifest 和证据哈希。不要对冻结目录批量格式化或做换行转换。

`XiAzir` 是个人布局分支：工程位于 `E:/VSCODE-project/FPGA-ANLU`，资料位于 `E:/QQ CACHE/Download/安路资料`。它用于原机器接续，不应直接覆盖 `main` 的公共路径改造。公共开发从 `main` 新建工作分支；更新记录时在资料仓也新建对应工作分支。

## 环境准备

| 依赖 | 用途与准备方式 |
| --- | --- |
| Windows、PowerShell 7、Git | 当前自动化入口使用 `pwsh`；Git 需支持长路径 |
| Python 3.9 或更新版本 | 核查、媒体生成和记录脚本；放入 PATH，或配置 `ANLU_PYTHON` 为解释器绝对路径 |
| Icarus Verilog 12 与 vvp | 本地逻辑模型；可用下方准备脚本获取已有 provenance 指定的版本 |
| Anlogic TD `6.2.1_SP1_6.2.178.840` | 当前正式综合、布局布线和位流生成使用的版本；按厂商安装流程独立安装 |
| TD 许可、BitWriter、AL-LINK 驱动 | 许可按厂商要求合法配置；驱动和 BitWriter 用于真实板卡下载，许可文件不在 Git 中 |
| Pillow（可选） | PNG 预览；核心 BMP 与逻辑模型数据生成使用 Python 标准库即可 |
| ffmpeg（历史媒体转换时） | 仅重新转换个人 M4A 原文件时需要；当前已交付 `TEST.WAV` 已入库，接续开发无需该 M4A |

从工程仓库根执行：

```powershell
pwsh -NoProfile -File ./scripts/setup_iverilog.ps1
$env:ANLU_IVERILOG_BIN = (Resolve-Path ./bringup/tf_wav_hdmi/tools/iverilog/app/bin).Path
# 将此示例改为实际 TD 安装目录中的 bin。
$env:ANLU_TD_BIN = 'C:/Anlogic/TD_6.2.1_SP1_6.2.178.840/bin'
python ./scripts/check_development_environment.py
```

准备脚本下载 provenance 固定的安装包，校验 SHA256，并用 innoextract 提取便携工具；不会运行 Icarus 安装器。已安装工具也可通过 `ANLU_IVERILOG_BIN` 或 PATH 使用。缺少工具时核查会退出失败并指出缺项。工具、许可和实体板卡需要准备好，单独克隆不能替代它们。

只核查仓库文件时使用：

```powershell
python ./scripts/check_development_environment.py --files-only
```

个人布局检查使用 `--docs-root 'E:/QQ CACHE/Download/安路资料'`。可选 `--all-checkpoints` 核查其他冻结 manifest；核查不会修补或跳过缺失文件。

## 源码、证据和素材入口

工程仓库中的 `development/player_bmp_scale/src` 是当前有效开发源码，`scripts` 是有效构建入口，`build/model` 是可运行模型。`checkpoints/bmp_scale_20261012_verified` 的 268 项清单是 C11206 冻结证据；其中旧脚本、旧日志和绝对路径记录保留构建时原貌。重新开发运行有效入口，冻结文件用于对照。

当前素材已在工程仓库内：四张原尺寸 BMP 位于 `development/player_bmp_scale/build/delivery/TF_ROOT`；预览图在同级 `PREVIEW_ONLY`，不可把预览图替代原始 BMP。当前 48kHz / PCM16 / 单声道 / 60 秒 `TEST.WAV` 位于 `deliverables/real_music_20261008/card/TEST.WAV`。发布包、展开副本、位流、照片、视频及清单均保留，用于版本复核。

实体 TF 卡、实验室板卡和原始个人媒体文件不是仓库文件。复制素材到真实 FAT32 卡或下载板卡时，按[当前版本已验证操作卡](../开发记录/专题记录/图片缩放/多尺寸最近邻首版_20261012/已验证操作卡.md)操作，使用当前位流与当前素材；旧版本回退要同时恢复对应旧素材。

## 接续模型与构建

环境及冻结文件核查通过后，在工程仓库建立开发分支并运行当前缩放与背压模型：

```powershell
git switch -c codex/continue-development
pwsh -NoProfile -File ./development/player_bmp_scale/build/model/scaler_full_loader.ps1
pwsh -NoProfile -File ./development/player_bmp_scale/build/model/run_write_backpressure.ps1
```

模型会在有效 `build/model` 中写入新日志和凭据，冻结 checkpoint 不变。完整缩放模型检查六帧 1,843,200 像素，并运行四种错误输入；背压模型检查实际写入后端握手。这些模型不能替代板卡、真实 TF 与音视频测试。

TD `.db` 与仿真 `.vvp` 属于生成产物，继续忽略。源码和工具具备后从综合启动新构建，生成属于新机器和当前输入的新阶段证据：

```powershell
pwsh -NoProfile -File ./development/player_bmp_scale/scripts/build_candidate.ps1 -Stage synthesis
pwsh -NoProfile -File ./development/player_bmp_scale/scripts/build_candidate.ps1 -Stage physical
pwsh -NoProfile -File ./development/player_bmp_scale/scripts/build_candidate.ps1 -Stage bitstream
```

如需要 hold 修复，按原入口执行 `-Stage hold` 后再生成位流。最终时序和完整阶段证据由构建入口校验，不能从另一机器的旧 physical/bitstream 状态直接续跑，也不能跳过门槛。新生成位流不默认继承 C11206 的用户实板反馈，须按改动范围重新验证，并记录新版本。`build/seal_candidate.py` 等封存脚本是版本专用流程，发布新版本前先更新版本标识和封存路径，避免覆盖旧版。

直接使用 TD GUI 保存后，可运行 `scripts/normalize_td_paths.ps1 -WhatIf` 预览，并在提交 `main` 工作分支前运行该脚本恢复有效 `.al` 的根路径；它不会修改冻结 checkpoint。
