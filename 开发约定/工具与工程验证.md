# 工具与工程验证

读取条件：使用 TD/BitWriter、创建或编译工程、检查时序、下载位流、Flash 固化，或排查工具错误时。工具信息截至 2026-10-05；后续变化按任务更新本文件及 [当前状态](../开发记录/当前状态.md)。

## 新克隆的工具准备

`main` 默认两个仓库位于同一父目录，布局和克隆命令见 [协作与目录](协作与目录.md)。克隆不会带来已安装的软件环境。需要另行安装适用的 Anlogic TD / BitWriter 并配置有效许可证；运行使用 Icarus 的仿真还需要安装 Icarus Verilog，确保 `iverilog` 和 `vvp` 可用。许可证与安装包不入库。工具版本、许可证/IP 兼容性以及本机编译和上板结果仍须在新环境重新验证。

活跃 PowerShell 脚本通过工程仓的 [scripts/anlu_tools.ps1](../../FPGA-ANLU/scripts/anlu_tools.ps1)发现工具。需要指定安装位置时，环境变量 `ANLU_TD_BIN` 指向 TD 的 `bin` 绝对路径；`ANLU_IVERILOG_BIN` 指向同时包含 `iverilog` 与 `vvp` 的目录绝对路径。未设置时先查找 `PATH`，再兼容仓库内 Icarus 与旧 TD 默认安装位置。兼容探测不替代软件安装、有效许可或环境验证，也不要求设置本机 Git 路径覆盖。

TD 打开或保存工程时可能把 `.al` 中的相对 `Project Path="."` 写回本机实际位置。`main` 提交前须检查并规范化这类本机绝对路径，不能把 GUI 自动保存后的文件直接视为可移植结果。历史或冻结工程保留原有证据；规范化针对本次维护的活跃工程输入。

正常的 TD PowerShell 包装脚本会在 `finally` 中恢复工程原有的根 `Project Path`。直接通过 GUI 或 Tcl 打开、保存工程后，可使用 [normalize_td_paths.ps1](../../FPGA-ANLU/scripts/normalize_td_paths.ps1)规范化。以下命令均从资料仓根目录 `FPGA-ANLU-docs/` 执行，先用 `-WhatIf` 预览，再执行不带该参数的命令：

```powershell
pwsh -File ../FPGA-ANLU/scripts/normalize_td_paths.ps1 -WhatIf
pwsh -File ../FPGA-ANLU/scripts/normalize_td_paths.ps1
```

该脚本只把 `bringup/`、`development/` 中活跃 `.al` 文件的根 `Project Path` 规范为 `.`，排除 `build/`、`checkpoints/`、`tools/`、`tmp/` 和 `*_Runs/` 中的冻结或生成内容。提交前仍需核对实际差异。

历史封存脚本依赖旧 manifest 中列出的数据库和一次性输出，其中部分已被 Git 忽略，新克隆不包含它们。这些脚本用于核对或封存对应的历史产物，不能作为新克隆的常规构建入口；缺项时须恢复与旧 manifest 一致的原始产物，不能删去缺项或绕过完整性、哈希校验来宣称封存成功。

相关一次性工具的显式输入接口为 `deliverables/build_real_music_package.py --source <原始媒体路径>`，以及历史反馈记录器的 `record_board_feedback_20261009.py --evidence-dir <原始证据目录>`。这些接口仅供接续对应的媒体打包或历史证据任务使用，不属于新克隆的默认执行步骤。

已有 `build_source_scope.json` 对应迁移前的 `.al` 文件字节。`main` 完成路径移植后，须从 `synthesis` 阶段重新建立源文件快照，不能直接复用旧快照进入 `physical` / `bitstream` 阶段，也不能绕过原有的完整性守卫。

## 工具与下载

- 下载器为 ANLOGIC AL-LINK，已识别 EG4S20BG256。
- 原开发机已安装 TD `6.2.1_SP1_6.2.178.840`，本机安装示例为 `C:/Anlogic/TD_6.2.1_SP1_6.2.178.840`；BitWriter `V1.2.178840`。这是历史环境记录，新机器按实际安装位置配置。
- 已使用 `PROGRAM_SRAM`、JTAG 5 MHz 下载小梅哥整板测试位流。5 MHz 是下载时钟，不是 FPGA 运行或 HDMI 时钟。
- `PROGRAM_SRAM` 写入 FPGA 配置 RAM，掉电丢失；与板上外部 SRAM 不是同一用途。Flash 固化与断电自启动须单独验证。
- 中文资料路径下添加 `.bit` 曾触发 BitWriter 打开失败和闪退；同一位流复制到英文项目路径后下载成功。保留原文件，不据此认定文件损坏或版本必然不兼容。

## 工程与验证

- 使用英文项目和位流路径，原厂参考保留在资料目录；复制所需工程后再修改、编译。
- 新工程明确时钟、复位、模块接口、引脚和 I/O 电平；按改动选择必要的仿真、构建和上板验证。
- 区分文件检查、源码静态核查、仿真、综合、布局布线/时序、下载及实物运行。综合通过不等于时序通过，下载成功不等于功能通过；现成位流成功不能替代本机编译、许可/IP 兼容验证。
- 随包 HDMI PLL 的生成值、请求值与 SDC 存在差异，像素/串行时钟被声明为 exclusive；尚未取得可证明高速链路通过的完整布局布线后时序报告。保留为重新编译时的核查项，不作为此前花屏的已证实原因。
- 涉及上述 HDMI 时钟疑点时，再读取 [HDMI 专题](../开发记录/专题记录/HDMI基础显示与供电排查/README.md) 对应段落与实际工程文件。
